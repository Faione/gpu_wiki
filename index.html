面向 CANN 的概念对应与适用范围

CANN 是昇腾软件栈，Ascend C 面向昇腾 AI Core 编程。后续应按目标产品与 CANN 版本核实具体资源和接口；本教程不把 NVIDIA Warp 当作所有加速器的通用线程组织。

可迁移的分析问题NVIDIA 中的例子昇腾中需要核实的机制
选择计算资源通用算术、Tensor CoreVector、Cube、Scalar 的职责与协作
安排数据驻留与复用寄存器、共享内存、缓存UB、L1、L0 等缓冲区及允许的数据路径
交叠搬运与计算异步复制与同步机制MTE、缓冲队列、多流水依赖与同步
分配工作并验证性能Grid / Block、资源占用与 profiling核间切分、核内 tiling、流水利用和实测耗时

这些是问题层面的对应，不是一一等价：昇腾 L1 Buffer 不等于 GPU L1 Cache；CUDA Local Memory 的线程私有语义也不同于昇腾 Local Memory 的片上缓冲语境。具体结构以 Ascend C 基础架构文档为准。

后续实践顺序：固定输入与正确性基线 → 测量当前实现 → 提出计算／搬运／同步假设 → 单项调整 → 比较性能与误差。目标型号、版本和算子尚未指定，因此当前不提供可直接套用的 tiling 参数。
