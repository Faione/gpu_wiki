第五章 · 从 token 到 GPU 上的计算与搬运

Transformer 的
软硬件执行

Transformer 的计算由线性投影、Attention、归一化和 MLP 等算子组成。本章追踪 token 的表示与张量形状，解释这些算子如何在 GPU 上分配工作、搬运数据并执行计算。

以单设备上的稠密 Decoder-only 模型为例，采用 Pre-Norm、RoPE 和 SwiGLU，并比较原始 Encoder–Decoder 与 GPT-2 的结构差异。交互实验计算张量形状、Attention 权重和存储容量，不预测 GPU 耗时。

5.1 从文本到模型：参数与运行时状态

Tokenizer 把文本转换为整数 ID；一个 token 不一定等于一个汉字或单词。Embedding 用 ID 从训练好的表 E 中取一行，组成 X。若词表大小为 Vocab、隐藏宽度为 D，E 的形状为 [Vocab,D]，X 为 [B,T,D]。ID 不是送进浮点矩阵乘法的词义数值。

同一个 Attention 公式，输入来源与可见范围不同
结构Q / K / V 从哪里来位置可以读取谁
原论文 Encoder同一源序列的隐藏状态全部有效源位置，屏蔽 padding
原论文 Decoder self-attention目标序列的隐藏状态目标位置自身及左侧前缀

原论文使用位置编码、LayerNorm 和普通 FFN；这里的 RoPE、RMSNorm、SwiGLU 是另一组常见选择，并非所有 Transformer 必须采用。原论文：Attention Is All You Need。

每层 KV cache请求的 Prefill 建立，Decode 追加保存该层各位置的 K/V，通常在设备内存；不是硬件 L1/L2 cache

模型参数量不会随 prompt 变长而增加；KV cache 会。Q 是本轮查询，未来 token 用的是新 Q，所以标准 KV cache 不存历史 Q。

5.2 完整的一层：把公式落实到张量

记 B 为请求数，T 为本次输入位置数，S 为可读取的 KV 总长度，L 为层数，Hq 为 Query 头数，Hkv 为 KV 头数，d 为每头宽度，D=Hq×d，F 为 MLP 中间宽度。MHA 有 Hkv=Hq；GQA 让 Hq/Hkv 个 Query 头共享一组 K/V；MQA 取 Hkv=1。共享不意味着所有 Query 头输出相同。

U = RMSNorm(X)                                 # [B,T,D]
Q = reshape(U WQ) ; K = reshape(U WK) ; V = reshape(U WV)
Q, K = RoPE(Q, K, absolute_positions)            # 对 Q/K 成对旋转
Kall, Vall = append_to_layer_cache(K, V)         # 推理时；保留层的身份
Z = softmax(Q Kallᵀ / √d + mask) Vall            # [B,Hq,T,d]
Y = X + concat_heads(Z) WO                      # 第一条残差
R = RMSNorm(Y)
Xnext = Y + (SiLU(R Wgate) ⊙ (R Wup)) Wdown      # 第二条残差
# 重复 L 层后：final_norm → LM head → logits → 采样 token ID

上述公式省略 GQA 的头索引广播：Query 头 h 使用 KV 头 ⌊h / (Hq/Hkv)⌋，要求 Hq 能被 Hkv 整除。Q 布局为 [B,Hq,T,d]，K/V 为 [B,Hkv,S,d]；不能在头数不同的情况下直接当作同形状批矩阵相乘。

RMSNorm 为每个 token 沿 D 计算平方均值：x / √(mean(x²)+ε) ⊙ γ；LayerNorm 还减去均值。它们引入归约依赖。RoPE 旋转每个头的特征对，使 Q/K 点积包含相对位置信息；缓存一般保存已旋转的 K。新 token 的绝对位置必须延续前缀，不能每轮从零开始。

一次前向中的算子账本（权重按 XW 的数学布局书写）
算子形状或核心计算主要 GPU 工作
QKV 投影[BT,D] × [D,(Hq+2Hkv)d]可合并投影为一次 GEMM；按输出块分给 Thread Block
QKᵀ每头 [T,d] × [d,S] → [T,S]批量矩阵乘；沿 d 归约
Mask + softmax沿 S 求 max、exp、sum，再归一化普通算术／特殊函数与归约；不是 Tensor Core 完成所有步骤
PV 与 WO[T,S] × [S,d]；[BT,D] × [D,D]矩阵乘；合并头可能需要布局变换
SwiGLU MLP两次 [BT,D] × [D,F]，一次 [BT,F] × [F,D]矩阵乘 + SiLU 与逐元素乘；无跨 token 混合
LM head[B,D] × [D,Vocab]（仅下一 token）词表投影、采样归约；训练通常对所有位置计算损失

Attention 混合不同位置，MLP 逐位置共享相同权重。“一层 Transformer”是模型结构，“一个 CUDA Thread Block”是一次 Kernel 的线程协作单位，两者不一一对应。一个模型层通常启动多个 Kernel；融合可能把相邻步骤合并。

5.3 从框架算子到 Warp 与矩阵单元

框架读取 shape、dtype、stride、mask 等条件，选择库或编译生成的 Kernel；运行时与驱动提交设备工作。SM 接收可驻留的 Thread Block，Warp 调度器发射已就绪的指令。数据依赖仍必须满足，同一 stream 的有序执行不是“CPU 等每个 Kernel 完成”。回读第三章的提交路径。

  1. 分配输出：以 QKV 投影为例，M=BT，N=(Hq+2Hkv)d，K=D。一个 Thread Block 常处理 BM×BN 输出块，多个 Warp 协作完成子块；并非一个 token 固定占一个 Warp。
  2. 供给数据：全局加载经缓存访问设备内存。块可把 X/W 的 tile 放入共享内存，Warp 以适合指令的布局读取；累加状态使用寄存器等片上资源。共享内存是显式协作存储，不是 HBM 与 L2 之间的必经缓存层。
  3. 发射计算：合适的形状、精度与实现可使用矩阵指令；归约、地址计算、掩码和激活仍由其他指令处理。Hopper / Blackwell 的异步矩阵指令和数据路径另见4.5，不能把某一种寄存器片段路径泛化到全部架构。
  4. 交叠与完成：下一块搬入可与当前块计算交叠，但使用前要等待数据就绪、覆盖前要确认消费者读完。更大 tile 提高复用，也可能占用更多共享内存／寄存器，减少驻留块数量。
融合减少的是哪些字节？

若 Norm 后的张量写到显存，后续 Kernel 再读一次，就多了一次中间张量往返。融合可减少这些访问和启动开销，但也会扩大活跃状态。优化应结合Roofline与资源预算，不能用“Kernel 数更少”直接判定更快。

5.4 Attention：数值、掩码与片上归约

设 Q=K=[(1,0),(0,1),(1,1),(−1,1)]，V=[(1,0),(0,2),(3,1),(−1,2)]，d=2。下面由这些数值实际计算权重；颜色与结果随掩码和 Query 行变化，不代表训练模型学到的词义。

Softmax 必须先沿一行找到最大值 m，再计算 exp(s−m) 和分母。这说明为什么“一线程一个输出元素”不能独立完成全部过程：同一行需要交换统计量。Warp shuffle 可交换 lane 数据，跨 Warp 协作可能借助共享内存与同步，具体组织由行长和 Kernel 决定。

FlashAttention 为什么不需要把 T×T 权重全部存回显存？

常规分步计算可把 scores / probabilities 物化为 [B,Hq,T,S]。融合实现按 Q/K/V tile 处理，将分数块和归约状态保留在片上，直接累计输出。它仍计算带 softmax 的 Attention，不能改写成 Q(KᵀV)，也没有把普通稠密 Attention 的计算复杂度降为线性。

对同一 Query 行逐块读取 K/V；s 已包含缩放与掩码：
m′ = max(m, max(s块))
α  = exp(m − m′) ; p块 = exp(s块 − m′)
ℓ′ = α ℓ + sum(p块)
o′ = α o + p块 V块
全部块完成后，输出 z = o / ℓ
初始 m=−∞，ℓ=0，o=0；全 masked 的块直接跳过。

m 改变时，旧分母与旧输出分子必须同时重标度；把各块 softmax 的结果直接平均会错。全行没有有效 Key 时需要显式约定输出，不能计算 −∞−(−∞)。这里每行至少包含自身。详细分块推导与实验见Attention Decode 专题第 5 节；作者实现与硬件支持说明。

5.5 训练、Prefill、Decode 的依赖为何不同？

阶段计算哪些位置并行性与状态
训练已知完整训练序列；位置 i 预测标签 i+1teacher forcing 允许一次处理多个位置，但用 causal mask 防止看到未来；反向依赖前向激活
Prefill输入 prompt 的 T 个位置每层生成全部 prompt K/V；位置间矩阵运算可批量执行；层与层依赖仍存在
Decode每请求一个新输入 token复用各层历史 KV，追加新 KV；本轮输出 token 才能成为下一轮输入

第一枚生成 token 来自 Prefill 最后位置的 logits。接着才把这枚 token 输入 Decode，计算它的 K/V 并预测第二枚生成 token。刚采样出的 token 还没有自己的 KV，直到它被作为输入经过各层。

假设 prompt 长度为 4：Prefill 计算位置 0…3，cache 长度为 4，采样位置 4 的 token；第一次 Decode 输入位置 4，cache 变为 5，采样位置 5 的 token。该约定也用于实验 A：Decode 的 S 包含刚追加的当前位置，进入前的 cache 长度是 S−1。

Decode 的 Query 长度为 1，但 Key 长度为 S；仍需读取整个可见历史。对“只有历史与当前项、没有 padding 的单 Query”可不再加 causal mask。直接把非方形 SDPA 的 is_causal=True 当作缓存位置偏移可能错误：PyTorch 的该语义为左上对齐。多 token 的 chunked prefill、批内不同长度和 padding 需显式构造正确的绝对位置 mask。参见SDPA 接口约定。

训练多了哪些硬件工作？

以 Y=XW 为例，反向需要 dX=dY Wᵀ 和 dW=XᵀdY，依然是矩阵乘，dW 还归约 token 维。Attention 反向需要对应中间量或重算，优化器读写参数与状态。Activation checkpointing 用重算减少保存的激活；普通训练通常关闭用于自回归服务的 KV cache。多设备训练还增加梯度等通信，不能仅按单 GPU GEMM 峰值推断速度。

5.6 参数、KV 与瓶颈：分别记账

对于上面的无 bias、两次 RMSNorm、SwiGLU、无可学习位置表模型，可用以下式子区分静态参数和运行时存储。Norm 参数也计入；若换回普通两矩阵 FFN，MLP 参数项是 2DF，不是 3DF。

P层 = D(Hq + 2Hkv)d + D² + 3DF + 2D
P总 = L P层 + D + Vocab·D × (权重绑定时 1，否则 2)
KV bytes = B × L × S × 2 × Hkv × d × bytes_KV
完整分数张量 bytes = B × Hq × T × S × bytes_score
某 GEMM：FLOP ≈ 2MNK
理想单次读取／写出字节 = (MK + KN + MN) × bytes
I = FLOP / bytes；t 下界 ≥ max(FLOP / P有效, bytes / BW有效)

最后两行是假设同一精度、每个输入只读一次且输出写一次的教学估计；真实 DRAM 流量受缓存、重复读、布局转换与融合影响。Roofline 下界也不包含所有启动、同步和通信延迟。回读第二章的量纲与边界。

实验 B · 改变缓存长度与精度

沿用实验 A 的 B、S、Hkv 与固定模型尺寸；Vocab=32000。调节实验 A 后，此处同步更新。

量化 KV 的实际占用还包含 scale、可能的 zero-point、对齐与分页开销；权重量化与 KV 量化是独立选择。总显存还包括临时激活、workspace、分配器保留空间与运行时资源。训练还需加入梯度和优化器状态；“模型权重装得下”不意味着推理一定装得下。

为什么 Prefill 常偏计算，Decode 常偏带宽？

Prefill 的线性层有许多输入行，同一权重 tile 可服务多个 token。小 batch Decode 的 M=B 很小，大量权重只服务少数行，复用较弱；长上下文还增加历史 KV 的读取。以 FP16 的 Q 投影、D=4096、B=1 为例：权重约 32 MiB，每轮约 33.55 MFLOP，忽略输入输出时约 1 FLOP/byte。增大 B 能提高权重复用，却同时增加 KV 和延迟。这些是瓶颈假设；短序列可能由启动开销主导，长 Prefill 的 Attention 也可能受访存限制。

GQA 减小 KV 的存储与投影宽度，但不会减少 Hq 个查询所需的逻辑注意力输出；只有实现实际复用共享的 K/V 时，带宽收益才会兑现。PagedAttention 将逻辑连续的 KV 映射到物理块，减少预留与碎片；这些 cache blocks 不是 CUDA Thread Blocks。FlashAttention 优化算子内部 IO，分页管理请求缓存，两者可结合。vLLM 的历史 PagedAttention Kernel 解析。

把分析方法迁移到昇腾

用 Cube 承载适合的矩阵任务，Vector 处理 softmax、Norm 等，按目标型号安排 GM、UB、L1/L0 和 MTE 数据搬运及流水同步。需要重新推导切块、布局与容量；不能将 Warp、SM、共享内存直接替换成某个昇腾术语。接着阅读已有 Ascend C 专题和4.7 的 CANN 衔接。

5.8 运行一个小模型，检验缓存等价性

下载 transformer_reference.py：一个两层、D=32 的随机权重 Decoder，包含 RMSNorm、RoPE、MHA、SwiGLU、残差与绑定 LM head。它不会下载 checkpoint，也不生成有意义的文本；用于检验每个 token 在完整 causal 前向和逐 token 缓存前向中得到一致 logits。

python3 examples/transformer_reference.py --device cpu
# 已有支持 CUDA 的 PyTorch 与 NVIDIA GPU 时：
python3 examples/transformer_reference.py --device cuda
# Apple Silicon 上，安装支持 MPS 的 PyTorch 后可运行：
python3 examples/transformer_reference.py --device mps

程序需要 PyTorch 2.x，使用 FP32 与容差比较，验证完整前向、先 Prefill 再 Decode、逐 token 解码，并对照显式 softmax 的 Attention。为了易读使用 torch.cat 扩展缓存，会反复复制；服务端应使用预分配或分页缓存。本例不支持 padding、GQA 或 chunked decode，也不作为性能基准。MPS 是另一硬件后端，不能用它证明 NVIDIA Tensor Core 的性能。

真正测量时要记录什么？

  1. 固定模型、B、prompt 长度、输出长度、dtype、后端、设备和软件版本；分开记录 Prefill 时间、首 token 延迟、稳态单 token 延迟与吞吐。
  2. 先预热，GPU 计时用设备事件或在计时边界同步；只测 Python 调用耗时可能测到的是提交时间。不要把模型加载混入稳态 Kernel 耗时。
  3. 用 profiler 查看 GEMM／Attention／Norm 的耗时与 Kernel 数，再结合 DRAM 流量、带宽、资源占用提出假设；若测服务，则另计排队、调度、采样和通信。
  4. 每次改变 tile、融合、精度或缓存布局后，比较 logits 或算子输出误差；生成文本相同不是充分的数值正确性检验。

理解检查

Decode 只输入一个 token，为什么计算不会变成常数开销？

每层仍读取模型权重并处理越来越长的 KV；标准密集 Attention 每轮计算随 S 增长。缓存省掉历史位置的重复投影和层计算，没有省掉当前 Query 对历史 Key 的匹配。

一个 Attention head 是否对应一个 Warp？

不是。head 是数学轴，Warp 是执行组织。一个 head 可以由多个 Thread Block／Warp 处理；具体映射由形状、切块与实现决定。

GQA 从 32 个 KV heads 改为 8 个，全部模型开销都降为四分之一吗？

在其他条件不变时 KV payload 为四分之一，K/V 投影也变窄；Query 头数、输出投影和 MLP 不因此变为四分之一。

FlashAttention 是靠忽略低权重位置来节省内存吗？

不是。它重排精确 Attention 的分块与归约，避免完整中间矩阵写回；浮点归约顺序可能产生误差，但不是稀疏近似算法。
