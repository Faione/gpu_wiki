第四章 · 从算子语义到计算硬件

矩阵乘法的软硬件实现

一次 MatMul 如何变成 GPU 上的数据搬运与乘加？本章沿同一计算逐层展开，将前三章的工作组织、数据供给和软件提交连接起来。

基础模型采用稠密矩阵、单 GPU、常见的 Block 分块与 Warp 级矩阵指令。Hopper、Blackwell 的路径变化在 4.5 单独说明；指令字段与接口约束见附录 15。

4.1 算子层：计算什么，哪些工作可以独立

矩阵乘法 D = A × B 中，A 为 M×K，B 为 K×N，D 为 M×N。每个输出 D[i,j] = Σₖ A[i,k]B[k,j]。M、N 决定输出空间，K 决定每个输出的归约长度。不同输出可独立计算，同一输出的部分和最终必须正确合并。

更一般的 GEMM（通用矩阵乘法）可写为 D = αAB + βC。下文取 α=1、β=0，以排除额外的 C 读取。按乘、加各计一次运算，主乘积约为 2MNK FLOP；这表示工作量，不是运行速度。

数学与分块背景：NVIDIA 矩阵乘法指南。

4.2 软件层：从矩阵接口到设备程序

软件不仅传递两个指针，还需说明尺寸、步长、输入与累加类型等。以行主序为例，A[i,k] 的地址偏移是 i × lda + k，lda 是相邻行起点间的元素距离，可能大于 K。转置标志也不必意味着先物理搬动整份数据。

接口依据：cuBLAS / cuBLASLt、CUTLASS 的主循环与输出处理分层。编译与提交链路见第三章 3.4。

4.3 工作分解：输出分块，K 方向分轮累加

为什么不简单地让每个线程独立读取一整行和一整列？这能表达正确算法，但相邻输出会重复使用很多输入。分块使这些复用发生在片上，并把任务整理成矩阵指令支持的形状。

以 64×64 输出块为例，可由 4 个 Warp 各负责一个 32×32 子块；在支持的实现中，再用多次 16×8×16 MMA 覆盖子块。这里 128 个线程协作持有 4096 个累加值，线程数不等于输出元素数。这一分工是示例，不是 Tensor Core 的固定物理布局。

每个 Block 完成自己的全部 K 轮次后写出结果，无需与其他输出块合并。若将同一输出的 K 维切给多个 Block（Split-K），则需要额外的部分和归约方案；它可能增加并行度，也会增加合并成本。

分层设计参考：CUTLASS Efficient GEMM；具体 Warp 指令形状见附15.4。本例不涵盖持久化 Kernel 的多输出块调度。

4.4 数据流：搬入、复用、累加与写出

// Block 级流程伪代码：表示职责，不是可编译 CUDA
acc = 0
for k0 in 0 .. K step BK:
    将本轮 A、B 子块搬入共享缓冲；越界输入按需填零
    等待数据可见且搬运完成
    各 Warp 加载片段，用多次 MMA 更新 acc

共享内存使一个输入值服务多次乘加；寄存器累加避免部分和反复往返显存。相应代价是片上容量与同步。全局访问合并和共享内存 bank 布局分别影响两段路径，不能用一种“连续访问”规则概括所有层次。

访存与复用依据：CUDA 分块矩阵乘法示例；输出融合属于 CUTLASS epilogue，不表示 Tensor Core 本身执行了所有激活函数。

4.5 硬件层：矩阵计算与搬运如何交叠

Tensor Core 是矩阵执行资源，MMA 是矩阵乘加操作。它们提高受支持矩阵运算的吞吐，但不负责完整 Kernel 的循环、地址计算和全部数据供给。控制、搬运、片上存储与算术资源需要协同工作。

架构演进改变了数据来源与协作方式

Blackwell SM100 的 tcgen05 路径引入专用于 Tensor Core 操作的 Tensor Memory，不能继续假设累加状态都在普通线程寄存器中按目标指令核实存储、协作范围及同步协议，不直接复制 Hopper 实现

增加流水阶段可扩大交叠机会，同时占用更多缓冲。矩阵块更大也可能需要更多累加空间。因此，“矩阵单元持续工作”与“尽可能多的 Warp 驻留”并不是同一个优化目标。

架构依据：Hopper TMA、PTX WGMMA、Blackwell SM100 GEMM及 Tensor Memory。表格用于区分路径，不是各代全部能力清单。

4.6 性能分析：分块为何存在相互制约

对一轮 K 分块，忽略额外搬运，输入元素数为 B_M×B_K + B_K×B_N，运算量为 2B_M B_N B_K。两种输入每元素均为 s 字节时：

本轮输入复用比 = 2B_M B_N / [s(B_M+B_N)] FLOP/byte

这是本 Block 对载入输入的复用量纲，不是包含输出、缓存和跨 Block 复用的实际 DRAM 算术强度。从公式可见，仅增加 B_K 不提高这一比值，却增加每份输入缓冲容量；增加 B_M、B_N 可提高复用，但累加空间按 B_M×B_N 增长，并减少输出块数量。

4.7 回到 Transformer 与 CANN

线性投影和 FFN 可从矩阵形状、输入复用和输出处理分析；Attention 则还要连接 QKᵀ → 缩放／掩码／Softmax → PV。归约、非线性和中间数据管理不因使用矩阵单元而消失。融合的价值需要从减少哪些读写、增加哪些状态与依赖来判断。

后续 CANN 实践可沿本章逐项填写：谁负责输出分块、K 轮次怎样推进、L1/L0 缓冲占用多少、Cube 与搬运能否交叠、尾块与 Vector 后处理怎样连接。具体 tiling、布局与同步接口应以目标设备和 CANN 版本为准。

昇腾数据路径与产品范围：Ascend C Basic Architecture。本章没有提供已验证的 CUDA 或 CANN 优化 Kernel。

完整理解链为：算子语义决定分块与依赖，分块决定数据复用和资源占用，指令与硬件决定可用计算路径，实测结果决定优化方向。具体实现问题再进入矩阵指令附录。
