附录 1：线程与执行状态

考虑一个没有线程间通信的任务：对 64 个数组元素分别加 1。程序只写一次 kernel，但每个线程使用自己的索引 i 和数据，形成不同的执行实例。

// CUDA 示例：每个线程计算一个元素
__global__ void add_one(const float* x, float* y) {
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    if (i < 64) y[i] = x[i] + 1;
}
add_one<<<1, 64>>>(x, y);  // 1 个 Block，每块 64 个线程

blockIdx.x 是块编号，blockDim.x 是每块线程数，threadIdx.x 是块内线程编号。这里创建的是 64 次逻辑执行，不是 64 套运算硬件。

线程 T0 的状态
i = 0
读取 x[0]，写入 y[0]

线程 T1 的状态
i = 1
读取 x[1]，写入 y[1]

附1.1 线程在硬件中的表示

这次启动不会在 GPU 内存中创建 64 个普通的 Thread 对象。线程由一组执行状态表示，这些状态分布在寄存器文件和控制结构中，并不要求集中存放为一个对象。SM 接收工作后，才为相应线程分配执行所需的片上资源。

线程身份
块编号、块内编号等硬件提供的索引信息，使各线程能够计算自己处理的元素位置。
数据状态
当前操作数和中间结果保存在编译器分配的寄存器等存储位置中。
执行进度
程序计数器等控制状态记录后续执行位置；现代 NVIDIA GPU 支持每线程执行状态。
参与与等待状态
活跃掩码标记一次指令中参与的线程；依赖跟踪等结构帮助判断指令能否发射。这些信息并非全部按线程独立保存，也会按 Warp 等粒度组织。

例如，T7 已加载 x[7] = 20，下一步需要加 1。即使它暂时没有使用运算单元，数值 20 和继续执行所需的状态仍可保留。获得发射机会后，数据被送入运算通道，结果 21 随后写回；同一通道之后可以服务其他线程。

寄存器和控制结构保存“线程执行到哪里、已有何种数据”；运算单元负责处理这些数据。线程持续存在，不要求它持续占用加法器。这也是后文“驻留”的基础。

源码变量与物理寄存器不是一一对应：编译器可能消除变量、复用寄存器或将部分数据放入内存。这里描述执行状态的类别，不是具体芯片的寄存器布局。参考：CUDA 硬件多线程、独立线程调度。

与 CPU 软件线程、SMT 硬件线程的关系

CPU 软件线程通常由操作系统安排到逻辑处理器上；CUDA 线程随 kernel 启动创建，由 GPU 按 Block 和 Warp 组织执行。SMT 硬件线程指 CPU 提供的一套体系结构状态，并不是操作系统管理的软件线程本身。三者都涉及执行状态，但调度层次不同。
