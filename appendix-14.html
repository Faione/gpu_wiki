附录 14：整数与浮点运算

同样是 32 位，整数与浮点数对这些位的解释不同，因此可表示的数值、运算电路与误差行为也不同。本篇以 CUDA C++ 中常见的 32 位整数与 IEEE 754 binary32（FP32）为例。

附14.1 位数相同，表示能力为何不同

32 位数据的两种编码

无符号整数 uint32_t32 位都用于整数位权精确表示 0 至 2³² − 1 的每个整数
常见二进制补码 int32_t有符号整数编码精确表示 −2³¹ 至 2³¹ − 1 的每个整数
FP321 位符号 + 8 位指数 + 23 位小数字段用有限有效位表示很大的动态范围，但数值间距不固定

整数相邻值相差 1。FP32 在不同数量级使用不同间距：所有绝对值不超过 2²⁴ 的整数均可精确表示，但在 2²⁴ 附近向上相邻值的间距已是 2。因此 16777217 不能精确存为 FP32。更大的范围并不等于更高的精度。

附14.2 运算电路为何不同

整数加法对固定位置的二进制位进行运算与进位传播，得到目标位宽的结果。浮点加法还需要处理指数差异和结果舍入；下图给出具体过程。电路职责更复杂不代表任意浮点指令都比任意整数指令慢，速度还取决于流水线配置与指令类别。

整数除法 7 / 2 在 C++ 整数类型下得到 3；浮点运算 7.0f / 2.0f 得到 3.5。除法、乘法与加法也不是同一硬件成本，不能只按“整数／浮点”两个标签比较速度。

附14.3 舍入与溢出是不同问题

整数加法、乘法的数学结果若在类型范围内，可以精确保存；超出范围则需按语言和指令规则处理。C++ 无符号运算按模 2ᴺ 处理，有符号整数溢出则不能依赖其回绕结果。

浮点运算即使没有溢出，也可能因为有效位不足而舍入。例如十进制 0.1 在二进制中是无限循环小数，只能近似保存。常用的“舍入到最近值，恰好居中时取偶数”中的“偶数”，指保留结果的最低有效位为 0。

附14.4 结合顺序与融合乘加

在 FP32 中取 a = 2²⁴、b = 1、c = −2²⁴，并在每步后按最近偶数舍入：(a + b) + c = 0，而 a + (b + c) = 1。原因是第一种顺序在计算 a + 1 时已经丢失了这个 1。

FMA 将 a × b + c 作为融合操作，最终舍入一次；分开的乘法与加法通常各舍入一次。并行归约改变求和顺序、编译器使用 FMA 等，都可能使 CPU 与 GPU 得到不同的末尾有效位，不能仅凭差异判定硬件出错。比较结果应结合数值范围与算法选用绝对／相对容差。

附14.5 在 GPU 程序中选择类型

线程索引、计数与位掩码通常需要整数语义；连续数值计算通常需要浮点。FP16、BF16、FP32、FP64 在范围和精度上各有取舍；低精度不只是存储更省，还可能改变可使用的矩阵指令和吞吐。宽类型也可能增加数据流量与寄存器占用。

核心内容：整数强调范围内的离散精确值，浮点用有限有效精度换取动态范围。选类型时同时检查表示误差、溢出、算法稳定性与目标设备支持，而不是一概认为浮点“更准确”或整数“必然更快”。
