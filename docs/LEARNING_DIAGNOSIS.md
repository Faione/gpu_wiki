## 三个可能的理解断点

| 回答依据 | 暂时判断 | 应补齐的解释 |
| --- | --- | --- |
| 独立线程“可能需要”Block；如果最终汇总则放在同一个 Block | 可能将 Block 理解成按协作需求可选的分组 | CUDA 线程始终属于 Block。Block 是分配工作的单位，也提供协作能力；无需协作时仍存在 Block。最终结果可通过多个 kernel 分阶段汇总 |
| 一个 64 线程 Block 与两个 32 线程 Block“大体相同，但是 block 越多，同步的代价越大” | 可能把同步范围的变化理解成单纯性能变化 | 块级屏障只能协调同一 Block。拆块可能要求改变算法，并非原同步操作只变贵。独立任务则可能根本无需同步 |
| 两个线程的加法是共同指令，“因为可能需要使用同一个加法器” | 指令组织与物理运算资源混在一起 | 共同指令规定相同操作，各线程提供自己的操作数。并不要求使用同一个加法器；物理单元的复用也不能反推 Warp 成员关系 |

## 教学调整

1. 以不需要汇总的逐元素加法开场，避免将 Block 等同于求和组。
2. 展示 `kernel<<<块数, 每块线程数>>>`，标明程序负责配置 Block，硬件按块内编号划分 Warp。
3. 对比一个 64 线程 Block 与两个 32 线程 Block：总线程数和 Warp 数相同，工作分配与块内同步范围不同；不从数量直接推导性能。
4. 将共同指令、各线程操作数、物理运算通道分开说明，提供贴近正文的小图。
5. 保留原映射实验，但将较大的编号图折叠为扩展阅读；NUMA 类比后置。
6. 详细解释仅在附录展开，正文保留必要定义。延续冷静、中立、简洁的教材语言。
