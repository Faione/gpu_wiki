附录 4：线程配置、编号与设计依据

附4.1 可配置的 Block 与固定的 Warp

开发者知道算法希望如何组织工作，因此 CUDA 允许程序在硬件限制内配置 Block 的数量、大小和形状。Warp 则采用架构规定的执行分组规则：程序配置 Block 后，Warp 的成员随之确定，不能另行任意指定宽度或拼接成员。

kernel<<<2, 64>>>(...);  // 2 个 Block，每块 64 个线程

B0：W0 = 块内线程 0～31；W1 = 块内线程 32～63
B1：W0 = 块内线程 0～31；W1 = 块内线程 32～63

程序可以计算 Warp 编号，再给不同 Warp 安排不同工作，也可以使用组内交换、投票或同步操作。这是在利用已有分组，而非重新定义分组。Cooperative Groups 创建的软件协作子组同样不会改变硬件 Warp 的宽度与成员。

两者分开配置的理由是：算法的工作组大小需要灵活，而调度、活跃掩码及操作数供给等机制需要明确的执行单位。固定 Warp 规则提供了稳定的组织基础；这是一种架构选择，不表示可变分组在技术上不可能。

附4.2 Warp 的编号与划分规则

NVIDIA 按每个 Block 内的线性线程编号，从 0 开始，每连续 32 个线程划为一个 Warp，不跨 Block。编号由线程坐标决定，不由数据地址、分支路径或当前任务决定。

// 将块内坐标线性化：x 最快变化，其次 y，最后 z
tid = threadIdx.x
    + blockDim.x * threadIdx.y
    + blockDim.x * blockDim.y * threadIdx.z;

warp_id = tid / 32;  // 整数除法，得到块内 Warp 编号
lane_id = tid % 32;  // Warp 内位置，范围 0～31

附4.3 编号约定与设计依据

规则是确定的，最优性不是定理。CUDA 明确规定 Warp 宽度及线程线性化方式，但这不意味着数学理论证明了“32 个线程、连续分组、x 优先”是唯一最优方案。以下是理解这些选择的工程分析，而非对具体芯片设计历史的断言。

  • 固定宽度：便于围绕稳定的组内位置设计掩码、调度和组内通信。更宽的组可分摊控制开销，但也可能在分支不一致或工作不足时留下更多不参与的位置；收益取决于工作负载与实现。
  • 连续编号：组号和组内位置可直接由除法、取余求出；对非负编号，除以 32 等价于右移 5 位，取余等价于保留低 5 位。这使映射易于计算和预测，不代表硬件不存在其他映射或状态管理。
  • x 优先：这是坐标线性化约定，不是物理定律。程序若让相邻编号访问相邻地址，可能有利于内存访问合并；编号连续本身不保证地址连续或最佳访存效率。

程序配置工作组，硬件按架构规则形成执行组，程序再根据已知规则安排工作与数据。规则可以被利用，但不能把软件子组、数据划分或物理加法器数量当作 Warp 的定义。
