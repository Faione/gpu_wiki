附12.2 算法复杂度与指令执行方式

SIMT 更便于直接表达每个线程的分支、循环和局部状态；它不意味着单条指令能完成更复杂的运算，也不保证复杂算法执行得更快。

“更复杂”所指的不同层次
比较方面SIMD 与 SIMT 的关系
算法表达SIMD 面向向量元素，SIMT 面向有各自状态的线程。SIMD 也能通过掩码、循环及标量代码配合实现复杂算法。
单条指令能力由具体指令集和执行硬件决定。SIMT 名称本身不代表支持更多运算或更复杂的指令。
执行效率取决于并行性、路径一致性与数据供给等条件。线程间路径越不同，共同执行的收益可能越低。

例如，同一 Warp 中的线程可以分别执行加法与乘法。以下代码假定使用一维 Block，各线程的 a、b、r 都是自身的局部值：

if (threadIdx.x % 2 == 0)
    r = a + b;
else
    r = a * b;
同一 Warp 的四个线程：不同操作如何执行
概念上的指令T0T1T2T3
加法参与不参与参与不参与
乘法不参与参与不参与参与

各线程最终执行了不同操作，但一次共同指令仍规定同一种操作。上表不是“同一次发射中，每个通道接收任意不同的指令”，也不规定真实执行顺序和周期数。编译器可能采用分支或谓词化；不同指令的执行能否交叠取决于依赖和硬件资源。

若线程各自循环不同次数，SIMT 也允许直接编写该循环；已结束的线程不再参与剩余迭代，成组执行的利用率可能下降。SIMD 可以用向量掩码组织同类计算，由程序或编译器安排哪些元素继续参与。

从 NVIDIA Volta（计算能力 7.0）开始，独立线程调度维护每线程的执行状态，支持更灵活的等待和推进，但仍将同一 Warp 中的活跃线程组织起来执行共同指令。它不为每个线程提供一套独占的指令发射通路。参考：NVIDIA：SIMT 与独立线程调度。

自测：一个线程做加法，另一个做乘法，是否违反 SIMT？

不违反。程序可以描述不同操作，执行时组织为相应指令及其参与线程集合。应区分“整个程序允许线程执行不同操作”和“一次共同指令是否允许任意不同操作”。

附12.3 寄存器写回、内存存储与同步

SIMD 通常将多个元素表达为一个线程的向量状态，SIMT 则保留多个线程各自的状态。这个区别影响协作方式，但不能据此认为 SIMD 的写回天然更原子。

寄存器写回：SIMT 中 T0 的 r 与 T1 的 r 属于不同线程，写入各自的寄存器不会相互覆盖，无需为每次加法添加线程同步。SIMD 写入向量寄存器时，整个结果就绪同样要求所需元素的结果均已产生；一条向量指令也可能在硬件内分多拍执行。

内存存储：竞争取决于访问地址及访问之间的顺序关系，而不是参与线程的数量。以下假设 i 是每个线程不同的索引，且没有其他冲突访问：

output[i] = r;  // 写不同元素：这些写入之间没有数据竞争
output[0] = r;  // 多个线程普通写同一位置：存在竞争

一条 SIMD 存储指令也不自动保证整个向量对其他执行者“同时可见”。内存原子性是指访问在相应观察范围内不可分割；其保证取决于具体指令、访问大小、对齐和体系结构，而非“是否只有一条指令”。寄存器结果就绪、内存写入对其他线程可见、整组写入具有原子性，是不同的问题。

跨线程协作：一个线程需要读取另一个线程的结果时，必须使用符合该通信方式的顺序与同步机制。同属一个 Warp 并不足以省略必要同步；多个线程独立计算并写入互不重叠的输出，则不因使用 SIMT 就必须互相等待。多个线程更新同一共享值时，通常需要原子操作或避免冲突的算法；写完后加一次屏障不能修复此前的竞争。

SIMD 将元素间操作表达在一个线程内部，SIMT 将跨线程协作显式暴露给程序。需要区分的是状态归属和通信方式，而不是“SIMD 原子、SIMT 不原子”。
