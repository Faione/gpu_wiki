附录 7：SIMD 与 SIMT 编程模型

附7.1 面向向量与面向线程

同样是“给数组中的每个元素加 1”，程序可以围绕一组数据编写，也可以围绕一个线程的工作编写。本附录先从这两种编程模型理解 SIMD 与 SIMT，再说明它们如何映射到硬件。

程序员描述的对象不同
编程模型代码表达程序员组织什么
SIMD：面向向量读取一组元素，对整组加 1，再写回向量数据、元素位置和参与运算的掩码
SIMT：面向线程当前线程取得自己的编号，对负责的元素加 1每线程的工作、局部变量与控制流，以及线程的启动配置
// SIMD 视角：向量伪代码，假设一次处理四个元素
X = load4(input + offset);
Y = X + broadcast4(1);
store4(output + offset, Y);

// SIMT 视角：单个线程的代码片段
i = 当前线程编号;
output[i] = input[i] + 1;

前者的一次向量操作描述多个元素，后者的代码描述一个线程，启动时再指定多少线程执行它。SIMD 也可以由编译器从普通循环自动生成，因此不要求所有源码都显式写出向量。

编程模型决定“代码以什么为单位描述工作”，硬件执行方式决定“指令如何使用运算资源”。以编程模型比较时，SIMD 面向向量，SIMT 面向线程；在硬件层面，SIMT 可以用 SIMD 式数据通路实现成组运算，两者并非互斥的电路设计。

附录 8：Kernel 的定义与启动

附8.1 函数定义与线程实例

在这里，kernel（核函数）是 GPU 并行计算的入口函数。它是一份程序代码，不是 GPU 核心、SM 或操作系统内核。以下采用 CUDA C++ 的 SIMT 模型：kernel 函数体描述每个线程执行什么，kernel launch（启动）指定线程如何分组以及传入什么参数。

// GPU 端：定义每个线程的工作
__global__ void add_one(const int* input, int* output, int n) {
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    if (i < n) output[i] = input[i] + 1;
}

// CPU 端：一次启动，1 个 Block，每块 64 个线程
add_one<<<1, 64>>>(d_input, d_output, 64);

__global__ 标记可通过 kernel launch 启动的 GPU 入口；<<<1, 64>>> 是执行配置，圆括号中才是函数参数。blockIdx.x 是块编号，blockDim.x 是每块线程数，threadIdx.x 是块内线程编号。本例只有一个 Block，所以 i 依次为 0～63。

普通函数调用通常由调用它的线程执行一次函数体；这里的一次 kernel 启动安排 64 个 GPU 线程各自执行同一函数体。再次启动同一个 kernel，可以换用不同参数和线程配置；kernel 函数与某一次启动不是同一个概念。

示例省略内存分配、数据传输和错误检查，假定两个指针指向 GPU 可访问的、足够容纳 64 个整数的数组。kernel 启动通常相对 CPU 异步，启动语句返回不代表 GPU 已完成；CPU 使用结果前需确保计算及必要的数据传输完成。参考：CUDA：Kernel 定义与启动。

附8.2 编译：分别生成主机代码与设备代码

一份 CUDA C++ 源文件可以同时包含 CPU 端代码和 GPU 核函数。nvcc 是组织编译流程的工具：主机部分由主机编译器生成 CPU 代码，设备部分生成 GPU 设备代码；主机代码中的 <<<...>>> 被转换为启动核函数所需的调用逻辑。

设备代码的几种表示
名称含义
PTX面向虚拟指令集的中间表示，仍需转换为目标 GPU 的机器码；GPU 不直接执行 PTX 文本。
cubin包含针对目标 GPU 架构生成的机器码及相关信息的设备二进制。机器指令的汇编表示常称为 SASS。
fatbinary设备代码容器，可包含多个目标架构的 cubin 和／或 PTX，通常嵌入主机程序或库中。

附8.3 加载：选择机器码或进行即时编译

运行时，CUDA 软件栈需要使设备代码可用于当前 GPU。若存在兼容的 cubin，可使用其中的机器码；需要使用 PTX 时，驱动可进行 JIT（即时编译），生成目标 GPU 的机器码。加载也可能按需延后，具体时机取决于配置和使用方式。

编译、加载与启动不是同一件事。同一个 kernel 可以在代码加载后启动多次，不必每次重新编译或重新传送整份代码。驱动还可以缓存 JIT 生成的二进制，以减少重复编译。

附8.4 启动：从 CPU 请求到 GPU 执行

CPU 执行 add_one<<<1, 64>>>(d_input, d_output, 64) 时，不是跳转到 GPU 指令地址，而是通过 CUDA 运行时和驱动提交执行工作。启动信息包括核函数、参数、Grid 与 Block 尺寸、动态共享内存大小和 stream；示例使用默认 stream，动态共享内存大小为零。

本例提交的是“一份代码由 64 个线程执行”的工作，不是 64 份机器码。核函数内部仍可能包含大量指令；kernel launch 也不是一次 Warp 指令发射。

启动通常相对 CPU 异步。教学程序可以使用 cudaDeviceSynchronize() 等待此前提交到设备的工作完成并检查返回错误；更细粒度的等待可使用 stream 或 event。同步本身不将结果复制回 CPU，若结果位于设备内存，还需安排相应的数据传输。

参考：NVCC：CUDA 编译流程、CUDA 平台：PTX、cubin 与 JIT 缓存。以上以 CPU 启动 CUDA C++ SIMT kernel 为范围，不展开运行时源码编译、设备端启动或 CUDA Graph。

附录 9：SIMD：向量、lane 与向量化

附9.1 标量指令与向量指令

标量加法指令处理一对标量操作数。SIMD（Single Instruction, Multiple Data，单指令多数据）则让一条指令对多个数据元素执行相同操作。例如，一个 128 位向量可容纳四个 32 位整数，一条向量加法可对四个位置分别求和。

图中的 lane 表示向量中的元素位置。四个 lane 属于同一个 CPU 线程的一次向量操作，并不表示四个 CPU 线程。图示只计加法指令，省略数据加载和循环控制；指令条数不能直接换算为运行时间。

附9.2 向量寄存器与 lane

lane 0、lane 1 等表示向量中的元素位置。128 位向量按 32 位整数解释时含四个 lane；按 16 位整数解释时可含八个。lane 数与数据类型有关，不是固定的线程数或核心数。

附9.3 典型场景与向量化

图像亮度调整、音频增益、数组逐元素运算以及批量比较，都包含对多份数据重复执行相同操作的工作。例如：

for (int i = 0; i < n; ++i)
    c[i] = a[i] + b[i];

编译器若将若干次循环迭代组合为向量加载、向量加法与向量存储，就是自动向量化；开发者也可通过向量内建函数等方式显式表达。尾部不足一个向量的数据，可通过掩码或标量代码处理，具体取决于指令集和编译器。

数学上的向量计算描述任务，SIMD 描述执行方式。同一个向量加法可以用标量循环、SIMD 指令或 GPU 上的 SIMT 实现；数组类型及源码中的向量写法本身不能证明使用了 SIMD。

附9.4 条件执行与适用限制

支持掩码的 SIMD 指令可以只让部分元素参与；其他实现可用计算后选择等方式处理逐元素条件。程序或编译器负责将这些条件组织为向量操作。SIMD lane 本身没有独立线程的程序计数器和调用栈。

SIMD 的收益依赖可成组处理的工作、有效的数据供给和足够的参与元素。循环依赖、复杂选路或分散访存可能限制向量化收益；数据连续通常有利，但不是 SIMD 的定义条件。支持 gather/scatter 的指令也能处理部分非连续访问。

参考：Intel：向量化与 SIMD、Intel：访问布局与 gather/scatter。

附录 10：SIMT：线程行为与成组执行

以下沿用核函数的执行模型：程序员编写每个线程的工作，启动配置产生多个执行实例。随后再观察硬件如何组织这些线程。

附10.1 程序层面：每个线程有自己的数据

SIMT（Single Instruction, Multiple Threads，单指令多线程）可以从两个层面理解：程序描述每个线程如何计算，硬件组织多个线程执行共同指令。

假设同一 Block 中的四个线程运行以下代码片段，输入数组为 [10, 20, 30, 40]：

int i = threadIdx.x;
int x = input[i];
int y = x + 1;
output[i] = y;
相同代码对应不同的执行实例
线程自己的 i自己的 x计算后的 y
T001011
T112021
T223031
T334041

T0 的 x 与 T1 的 x 是不同的局部值，不会互相覆盖；变量是否存入寄存器由编译器决定。若代码包含 if 或循环，各线程根据自己的条件选择分支或循环次数，这就是“每个线程有自己的控制流”。

附10.2 硬件层面：共同操作成组执行

当这四个线程执行 x + 1 时，硬件可以发射一条共同的加法指令，让各线程分别提供 10、20、30、40，并将 11、21、31、41 保存为各自的结果。操作控制共同使用，数据仍然分别归属各线程，因此数据处理方式与 SIMD 相似。

活跃线程指参与当前这条指令的线程。例如某条分支只有 T0、T2 需要执行加法，本次便只由它们参与；T1、T3 仍属于原来的 Warp，只是不参与这条指令。这种成组执行限定在同一 Warp 内，并非从所有线程中任意拼组。

SIMD 的一条向量指令描述多个元素的运算；SIMT 允许程序分别描述各线程的计算，再由硬件组织共同指令的执行。线程是独立的计算实例，并不因此拥有独占的运算硬件。

四线程示例用于说明数据归属，不改变 NVIDIA Warp 的 32 线程宽度，也不表示一次加法必然在一个周期内完成。

附10.3 工作映射与访存

SIMT 程序需要确定每个线程负责哪些数据，例如每线程处理一个像素、一个数组元素或一个粒子。线程并不只能处理一个元素，也可以在自身循环中处理多个元素；Block 则组织需要协作的线程。

每个线程可以计算自己的地址，共同指令不要求这些地址相同。相邻线程访问相邻地址，通常有利于合并内存请求；分散访问虽可表达，却可能需要更多内存事务。线程间共享数据时，还需按通信范围使用同步机制，不能把“同一 Warp”当作隐含同步保证。

线程数、驻留数量和实际执行通道数属于不同层次，详见附录 5.2：Warp 与 SM 的关系。

附录 11：Warp 发射与分支分歧

附11.1 线程状态与成组发射

在 NVIDIA GPU 中，一个 Warp（线程束）包含同一 Block 内连续编号的 32 个线程。它们保留各自的数据状态，但在执行共同指令时共享发射。这样，控制与发射开销可以由多份数据运算分摊。

以下 Block 有 64 个线程，因而分成 W0 与 W1。示例中每个线程依次计算 r = x + 1 和 y = r × 2，且初值 x = 线程编号。选择一个 Warp 并发射下一条指令，可观察哪些线程的状态发生变化。

例如，W0 执行加法时，T0 得到 r = 1，T1 得到 r = 2。它们执行同一条加法指令，但读取和写入各自的寄存器。W1 的状态此时保持不变；两个 Warp 的执行进度可以不同。

Warp 是线程的执行分组，SM 才是提供调度与运算资源的硬件。32 个逻辑线程不意味着独占 32 个物理算术单元，也不保证每条指令在一个周期内完成。

本实验将发射与结果完成合并为一个可视步骤，并假设操作数及执行资源已就绪。实际调度由硬件决定，指令的延迟、吞吐与所用执行管线取决于架构和指令类型。

附11.2 分支路径与活跃掩码

共同发射要求本次参与的线程执行同一条指令。当线程选择不同路径时，可分别执行各路径的指令，并用活跃掩码标记本次参与的线程。Warp 的成员编号保持不变。

这解释了分支分歧（divergence）的代价：某条路径的指令仍需执行，但只有部分线程参与，能够利用的逻辑 lane 比例降低。路径越不一致，成组执行的收益通常越受限制。

实际执行与同步的进一步说明

图中用两次带掩码的操作说明语义，不模拟编译器生成的指令；短分支也可能采用谓词化。现代 NVIDIA GPU 支持独立线程调度，不能假定 Warp 内所有线程始终严格同步前进。线程间交换数据仍应使用与通信范围相符的同步机制。

附12.2 算法复杂度与指令执行方式

SIMT 更便于直接表达每个线程的分支、循环和局部状态；它不意味着单条指令能完成更复杂的运算，也不保证复杂算法执行得更快。

“更复杂”所指的不同层次
比较方面SIMD 与 SIMT 的关系
算法表达SIMD 面向向量元素，SIMT 面向有各自状态的线程。SIMD 也能通过掩码、循环及标量代码配合实现复杂算法。
单条指令能力由具体指令集和执行硬件决定。SIMT 名称本身不代表支持更多运算或更复杂的指令。
执行效率取决于并行性、路径一致性与数据供给等条件。线程间路径越不同，共同执行的收益可能越低。

例如，同一 Warp 中的线程可以分别执行加法与乘法。以下代码假定使用一维 Block，各线程的 a、b、r 都是自身的局部值：

if (threadIdx.x % 2 == 0)
    r = a + b;
else
    r = a * b;

各线程最终执行了不同操作，但一次共同指令仍规定同一种操作。上表不是“同一次发射中，每个通道接收任意不同的指令”，也不规定真实执行顺序和周期数。编译器可能采用分支或谓词化；不同指令的执行能否交叠取决于依赖和硬件资源。

若线程各自循环不同次数，SIMT 也允许直接编写该循环；已结束的线程不再参与剩余迭代，成组执行的利用率可能下降。SIMD 可以用向量掩码组织同类计算，由程序或编译器安排哪些元素继续参与。

从 NVIDIA Volta（计算能力 7.0）开始，独立线程调度维护每线程的执行状态，支持更灵活的等待和推进，但仍将同一 Warp 中的活跃线程组织起来执行共同指令。它不为每个线程提供一套独占的指令发射通路。参考：NVIDIA：SIMT 与独立线程调度。

自测：一个线程做加法，另一个做乘法，是否违反 SIMT？

不违反。程序可以描述不同操作，执行时组织为相应指令及其参与线程集合。应区分“整个程序允许线程执行不同操作”和“一次共同指令是否允许任意不同操作”。

可以。成组执行要求本次参与的线程执行共同指令，不要求它们的数据相同。若 T0 与 T1 走向不同分支，它们仍属于原来的 Warp，只是在执行某条路径时可能有不同的活跃状态。
