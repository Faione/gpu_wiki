附录 15：矩阵指令与 Tensor Core

矩阵指令把一块规则的乘加工作交给专用执行资源。本篇以 NVIDIA 的 Warp 级矩阵乘加为主，分别解释数学操作、线程持有的数据与硬件执行。CPU 的部分矩阵扩展也面向类似问题，矩阵计算并非 GPU 独有。

若要先建立从软件到硬件的完整链路，可阅读第四章：矩阵乘法的软硬件实现。本篇作为指令与接口参考。

附15.1 一次矩阵乘加计算了什么

D = A × B + C 中，若 A 为 M×K、B 为 K×N，则 C、D 都是 M×N。每个输出 D[i,j] = Σ A[i,k] × B[k,j] + C[i,j]；K 是每个输出累加的乘积数量。

附15.2 API、指令与物理单元是三个层次

库组织完整 GEMM，WMMA／PTX 表达受约束的矩阵子操作，目标机器指令由 SM 执行。这些层次的入口与责任见第四章 4.2，下面直接说明线程片段和指令约定。

附15.3 矩阵数据如何分布到线程

普通 SIMT 加法常可理解为“每个线程计算自己的一个结果”。Warp 级 MMA 则是一组线程共同提供矩阵操作数，并共同持有输出片段。每个线程仍有自己的寄存器，但这些寄存器中的值合起来构成矩阵块。

一个 Warp 的协作视角
矩阵块 A、B → 分布在各线程中的片段线程 0 持有一部分，线程 1 持有另一部分，……；不是每线程各存一整块。
↓ 共同执行规定的矩阵指令
结果片段 → 各线程的累加器寄存器 → 存储输出矩阵块逻辑矩阵元素与线程寄存器的映射由所用接口或指令规定。

在 CUDA WMMA 中，fragment 封装每线程持有的那部分数据，元素映射不是可随意假设的通用布局。Warp 内线程应按接口要求共同执行相关操作；只让线程 0 调用 mma_sync 不能代表整个 Warp 完成计算。同步式矩阵操作也不代替此前生产输入数据所需的内存同步。

附15.4 解读一条具体矩阵指令

mma.sync.aligned.m16n8k16.row.col.f32.f16.f16.f32
    d, a, b, c;

这是省略具体寄存器列表的 PTX 示意，适用于支持该形式的目标（此 FP16 形式要求 sm_80 或更新的受支持目标）。A 是 16×16，B 是 16×8，C 与 D 是 16×8；一个 Warp 协作完成这项逻辑操作。

指令字段的含义
字段解释
m16n8k16M=16、N=8、K=16，不是 16 个线程或 16 个周期
row.colA、B 的布局约定；实际寄存器片段映射需查指令文档
f32.f16.f16.f32按 D、A、B、C 的次序指定类型：FP32 输出／累加，FP16 输入
sync.aligned要求 Warp 按规定共同执行该指令；这里的 aligned 不是数组地址对齐的替代检查

按一次乘法与一次加法各计一个浮点操作，工作量为 2×16×8×16 = 4096 FLOP。这是整个 Warp 这项操作的计数，不应再乘 32，也不是每周期性能。实际寄存器操作数、执行时间及支持类型由架构与指令形式决定。

附15.5 混合精度能保留什么、不能保留什么

常见方案使用较低精度输入、较高精度累加。例如 FP16 输入配 FP32 累加，可以降低输入存储与传输成本，并让累加使用更宽的表示。但输入转换时已丢失的信息不会由 FP32 累加恢复。

FP16 与 BF16 都占 16 位，但前者通常有更多有效精度，后者有更宽指数范围；FP32 有更高有效精度。具体矩阵指令支持哪些组合取决于架构。矩阵累加的次序及舍入规则也不应简单等同于整个表达式只舍入一次的标量 FMA。

附15.6 一块矩阵怎样真正执行

沿 K 分块时，同一个累加器按 acc ← acc + A_tile × B_tile 反复更新；输入缓冲轮换，输出位置不变。相应的数据反馈回路见图 4-3，缓冲何时可读、何时可覆盖见图 4-4。

CUDA WMMA 如何表达一个 16×16×16 子块？

以下仅是 Kernel 内结构性片段，不是完整程序。假设使用支持的 GPU、包含 <mma.h>，且整个 Warp 一致执行；A、B 为 FP16，D 为 FP32，三者是已准备好的行主序 16×16 连续块，指针满足 32 字节对齐，leading dimension 为 16；此前所有写入已正确同步。

using namespace nvcuda;
wmma::fragment<wmma::matrix_a, 16, 16, 16,
               __half, wmma::row_major> a;
wmma::fragment<wmma::matrix_b, 16, 16, 16,
               __half, wmma::row_major> b;
wmma::fragment<wmma::accumulator, 16, 16, 16, float> acc;
wmma::fill_fragment(acc, 0.0f);
wmma::load_matrix_sync(a, A, 16);
wmma::load_matrix_sync(b, B, 16);
wmma::mma_sync(acc, a, b, acc);
wmma::store_matrix_sync(D, acc, 16, wmma::mem_row_major);

此 API 的 16×16×16 形状与前面的 PTX 16×8×16 示例不同，不能直接按一次调用一条指令对应。本段未在 GPU 上编译或运行验证。

附15.7 专用单元何时有效

大块、规则、可复用的数据容易摊薄装载、重排与提交成本。小矩阵、稀疏或不规则数据、精度要求不匹配，以及缓存或显存供给不足，都可能限制收益。矩阵边界不满足 tile 形状时，还需合法填充或其他边界处理，不能直接让一部分必要参与线程跳过指令。

核心内容：矩阵指令扩展了共同指令所表达的工作粒度：线程协作完成一个矩阵块，而不是各自任意执行不同操作。它依然需要正确的数据组织、同步和数值精度选择。通常先使用成熟矩阵库，再根据测量决定是否下沉到 WMMA 或 PTX。
