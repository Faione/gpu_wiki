第一步 / 区分目标

1.1 单任务延迟与整体吞吐量

数组元素之间不存在数据依赖时，不同元素的计算可以并发执行。任务独立性是本例能够利用并行资源的前提。

01 · 问题

为什么单个任务完成较慢的处理器，仍可能更早完成整批任务？CPU 与 GPU 的资源配置差异应当用哪些性能指标解释？

02 · 背景

Latency-oriented

优化单个任务从开始到完成的时间。典型 CPU 会用复杂控制逻辑、较大的缓存和推测机制减少单线程停顿。

Throughput-oriented

优化单位时间完成的总工作量。典型 GPU 把更多预算交给并行算术与线程状态，以容纳大量并发工作。

三种并行性

ILP
一条指令流内，互不依赖的指令重叠执行。
TLP
多个线程或线程束并发推进。
DLP
同一种操作作用于许多数据元素。

本章数组计算的不同元素互不依赖，因而可以同时分配给多个执行资源。面积和功耗有限，使得每个执行资源的能力与可配置数量之间存在取舍。

数组计算中的三种并行性

同一个线程提前加载多个互不依赖的 x[i]，使独立指令重叠执行，是 ILP（指令级并行）。将不同 i 分配给不同线程，是 TLP（线程级并行）。对多个 x[i] 执行相同的乘加运算，体现 DLP（数据级并行）。三者可以同时存在。

03 · 底层逻辑与解决方式

独立任务的执行时间对比

16 个独立任务。机器 A 有 1 个执行资源，每任务耗时 2；机器 B 有 4 个资源，每任务耗时 4。时间单位任意，忽略启动、访存、流水线和争用。

A：首个结果 t = 2
整批完成 t = 32
吞吐量 0.5 个任务 / 时间单位

B：首批结果 t = 4
整批完成 t = 16
吞吐量 1 个任务 / 时间单位

任务间存在顺序依赖时的结果

若每项任务均依赖前一项的完成结果，B 同时只能使用一个执行资源：A 总耗时 32，B 总耗时 64。硬件并行需要程序提供独立工作。本例只区分指标，不预测 CPU/GPU 性能。

缓存影响数据何时返回，调度影响等待期间还能做什么。两者都可能改善资源利用率，不能从“缓存多”直接推导“吞吐低”。预算取舍的详细推导见 附录 18。

04 · 核心内容提炼

  • Latency 衡量单任务完成时间，Throughput 衡量单位时间完成的工作量；较高吞吐量不要求每个任务的延迟都更低。
  • 控制与缓存可通过减少有效停顿改善执行时间；算术资源数量影响运算能力上限。资源投入不直接等于性能。
  • 实际收益受任务独立性、数据局部性、带宽及有效利用率约束。CPU 与 GPU 都利用多种并行性，区别在于设计重心。

任务独立性并不能保证执行单元持续运行；操作数未就绪时，依赖指令仍会停顿。下一节讨论 CPU 对这类停顿的处理机制。 继续 →

第二步 / 分析停顿原因

1.2 执行资源可用性与指令就绪条件

乘法依赖 x[i] 的加载结果。执行资源空闲并不意味着存在满足发射条件的指令。

01 · 问题

当乘法单元空闲时，处理器为什么仍不能执行 y[i] = 2 × x[i] + 1？若计算资源已经存在，增加同类资源能否解决这个停顿？

02 · 背景

执行指令需要同时满足操作数、依赖关系和硬件资源等条件。这里重点讨论真实数据依赖：一条指令必须获得前序指令产生的值，才能计算正确结果。资源空闲只满足其中一个条件。

在上述链条中，加载结果未返回时，乘法的源操作数不可用；乘法未完成时，加法也无法获得其结果。同一时刻，另一条 z = a + b 若操作数已就绪且不依赖 x[i]，则可能具备执行条件。

03 · 底层逻辑与解决方式

停顿的直接原因是缺少满足执行条件的指令。处理器可以缩短条件尚未满足的时间，也可以在这段时间执行其他独立指令。控制路径未确定时，还可以通过预测与推测提前推进取指和执行。

缓存可缩短数据等待；乱序执行利用同线程的独立指令；SMT 引入其他线程的候选指令。它们都不消除真实数据依赖。GPU 接下来扩展的是可驻留、可调度的工作来源。

CPU 的 OoO、SMT、缓存与推测执行可组合使用。机制对照实验见 附录 18.2；这里保留“依赖就绪与资源可用必须同时满足”这一前提。

OoO 与 SMT 可以共同工作

OoO 增加指令执行安排的灵活性，SMT 增加指令的线程来源。二者可以同时存在，不是先使用 OoO、失败后才切换到 SMT；最终能否执行仍取决于依赖、就绪状态和共享资源。

04 · 核心内容提炼

  • 执行资源空闲是指令可执行的必要条件之一，操作数就绪与依赖满足同样重要。
  • Cache 缩短部分访问等待；OoO 用同线程独立指令覆盖等待；SMT 从其他硬件线程补充候选指令。
  • 分支预测与推测执行处理控制路径的不确定性。所有机制都有适用条件，其收益取决于程序能够提供的独立工作。

独立指令的来源可以扩展到多个线程。下一节先讨论这些工作的组织方式，再引入具体 GPU 结构。 进入 1.3 →

第三步 / 从通用原理推导执行组织

1.3 从独立指令到多线程执行

本节从程序中的独立工作出发，说明保存线程状态与成组发射的理由，为下一节的 GPU 调度机制建立前提。

01 · 问题

单个线程中的独立指令有限，而程序还包含大量互不依赖的任务时，硬件如何获得更多可执行工作？

02 · 背景

上述机制围绕同一个问题：当前指令等待时，还有哪些工作可以执行？OoO 在同一线程中寻找独立指令，SMT 将来源扩展到其他线程。下一步讨论的不是另一套依赖规则，而是当独立工作很多时，如何组织这些工作。

独立工作来自程序。对于数组计算，单个元素内部仍有“加载 → 乘法 → 加法”的依赖，但不同元素之间没有这种依赖。可以让多个线程分别处理不同元素：线程 T0 等待 x[0] 时，T1 仍可能发出自己的加载，或计算已经返回的数据。创建线程是在表达已有的独立性，并不能消除原有依赖。

03 · 底层逻辑与解决方式

交替推进需要保留状态。硬件若要在许多线程之间选择工作，就需要保留它们的数据和执行进度，使某个线程等待时，其他线程能够继续。这与 SMT 的基本思路相通；对于大量独立任务，面向吞吐量的设计更重视可同时保留的线程状态规模。

大量相同操作适合成组组织。数组线程通常执行相同操作、处理不同数据。硬件可以让一组线程共享共同指令的发射，以分摊控制开销，同时在不同组之间选择就绪工作。这样，讨论对象便从“一个线程中的候选指令”扩展到了“多个线程组提供的候选指令”。

在 NVIDIA GPU 中，这种线程执行组称为 Warp，承载其状态、调度与运算资源的硬件组织称为 SM。多个 Warp 可以驻留在同一 SM；具体组成与对应关系见附录 5.1及附5.2。

04 · 核心内容提炼

这里得到两个硬件需求：保存多组执行状态，以及从中选择就绪指令。下一节以 NVIDIA GPU 为具体实例，为这些组织引入名称，并观察它们如何覆盖等待。CPU 与 GPU 都可以利用线程级和数据级并行；这是设计侧重点的比较，不是二者的绝对划分。

第四步 / 扩大调度候选范围

1.4 驻留执行组之间的交叠执行

上一节由独立工作推导出“保存多组状态、选择就绪指令”的需求。本节以 NVIDIA GPU 为例，说明这种组织如何使不同工作的等待区间交叠。

01 · 问题

当单线程能够提供的独立指令不足以覆盖长延迟时，GPU 如何保持执行资源持续利用？增加线程数量为什么可能有帮助？

02 · 背景

在 NVIDIA 的术语中，共同组织指令执行的线程组称为 Warp，保存线程状态并提供调度与运算资源的物理单元称为 SM。当一组的状态及所需资源已保留在 SM 上，就称为驻留。因此，“驻留执行组”在本节具体指驻留的 Warp；这些名称对应的是前节已经引入的执行需求。

驻留仅说明资源已分配；该组的下一条指令仍须操作数就绪、满足依赖等条件，才能参与发射选择。以下时间线假设各组已经驻留，重点观察它们如何交替发射指令。线程如何组成 Block、如何分配到 SM，以及组内如何共同执行，分别在附录和 1.5 节展开。

03 · 底层逻辑与解决方式

1.4.1 两个 warp 的六周期示例

假设只有一个发射槽，每周期最多发射一条 warp 指令。W0、W1 均已驻留，各自执行“加载 → 依赖该加载的加法”。加载在周期 t 发出，数据在 t + 4 周期开始时可用。两个加载可同时处于未完成状态。本例忽略带宽竞争和其他指令。

W1 的加载在 W0 访存尚未完成时已经发出，两个操作的等待区间发生重叠。即使每周期仅发射一条指令，多条此前发射的操作仍可能同时在不同流水线或存储系统中进行。

该过程在 6 个周期中使用了 4 个发射槽。两个 warp 只能覆盖部分等待；若存在更多独立且就绪的 warp，周期 3～4 可能被其他指令使用。

1.4.2 更多线程为何不一定消除空档

调度逻辑跟踪指令依赖与资源状态。某组缺少操作数时，其他组只有在自己的下一条指令也符合条件时才可被选中。所有驻留组都等待数据或同步条件时，即使线程数量很大，也可能没有可发射指令。

增加 warp 数量扩大的是候选集合，而不是每周期的发射槽数。它不能缩短每一次访问，也不能突破存储带宽或算术流水线的容量。

1.4.3 固定依赖间隔的调度模型

上例区分加载与加法。下方实验进一步简化：每个 warp 有持续的待执行工作，每次发射后，其下一条指令都在 L 周期后才允许发射；没有任务完成与退出。它用于单独观察驻留数量与等待间隔的关系，不是数组程序的完整仿真。

每行是一个 warp，每列是一个周期。● 表示该周期发射，– 表示等待依赖，· 表示就绪但未被选择。空白表示尚未播放到该周期。利用率是已经发射的槽数除以已经观察的周期数，而不是完成的任务比例。

例如 L = 8 时，周期 1 发射的 W0 在周期 9 最早再次就绪。只有一个 warp 时，周期 2～8 没有候选；8 个初始就绪的 warp 则可以依次填入这些周期。W0 的间隔始终保持为 8 周期。

24 周期内发射槽利用率的计算

模型只有 1 个发射槽 / 周期，所有组初始就绪。L = 8 时，1、4、8 个 warp 分别发射 3、12、24 次，利用率为 12.5%、50%、100%。这一模型不模拟真实指令混合、带宽竞争或多个调度器。100% 仅指本例发射槽无空档，不代表 GPU 达到峰值性能。

实验对照：三个预设固定 L = 8。单组预设显示等待空档，四组预设显示部分覆盖，八组预设显示完全覆盖。“回到周期 0”可从初始状态单步查看；播放过程中每条说明对应一个发射决策。

04 · 核心内容提炼

  • 独立指令不足时，其他线程可以提供额外工作；这是从 CPU SMT 过渡到 GPU 多线程调度的概念联系。
  • 线程状态描述每个执行实例的进度与数据；驻留意味着相应状态及资源已保留在执行单元上，不意味着独占算术通道。
  • Warp 是线程组。Ready 表示指令符合选择条件，Issued 表示获得一次发射机会，发射不等于完成。
  • 交叠执行让其他组的工作占用部分等待区间，提高资源利用率；原组的延迟可以保持不变。
  • 候选组必须独立且就绪，收益还受驻留容量、发射能力与数据供给限制。
练习：等待数据的 Warp 是否仍然驻留？

等待数据的 Warp 仍可保持驻留。此时变化的是后续指令的就绪条件，W0 已分配的寄存器等状态仍保留。它可以同时处于“已驻留”和“等待依赖”的状态。

练习：驻留数量是否决定每周期发射数量？

驻留数量描述候选组的规模，每周期发射数量还受发射槽数和指令就绪情况限制。若只有一个发射槽，则每周期最多选择其中一组的一条指令；其余组可能等待依赖，也可能已经就绪但未被选中。

练习：交叠执行是否缩短单次加载延迟？

本模型中 W0 的加载延迟保持不变，性能改善来自 W1 的工作与 W0 的等待交叠。真实硬件中并发请求还可能造成资源竞争，因此隐藏延迟也不意味着单次访问延迟必然保持不变或下降。

成组发射可以分摊控制开销，但组内线程选择不同路径时会产生执行约束。下一节讨论共享指令与分支分歧的关系。 继续 →

第五步 / 理解成组执行

1.5 共享一条指令，处理不同数据

数组计算中的线程执行相同的乘加运算，各自处理不同的 i。共同发射指令能够分摊控制开销，适用于此类数据级并行。

01 · 问题

GPU 为何将大量线程成组发射？同一组线程选择不同分支时，共享指令的执行方式如何保持每个线程的程序语义？

02 · 背景

SIMD 与 SIMT 的语义关系

CPU SIMD：向量指令处理 [x0, x1, x2, x3] × 2。GPU SIMT：程序写单个线程的 x[i] × 2，机器将线程分组执行。SIMD 是 Single Instruction, Multiple Data；SIMT 是 Single Instruction, Multiple Threads。SIMD lane 表示向量中的元素位置；Warp lane 表示线程在 Warp 内的位置，两者都不应直接等同于独占的物理运算电路。

加入 if (x[i] > 0) 后，组内线程可能选择不同路径。Active mask 指定当前路径哪些线程参与，其他线程暂不产生该指令的效果。

观察角度CPU SIMDGPU SIMT
程序员看到显式向量值与向量指令许多标量线程及其私有状态
硬件组织一条指令驱动多个 lane线程按 warp / wavefront 分组发射
控制流常用 mask / predicate分歧路径按 active mask 执行并再汇合

术语：warp 是 NVIDIA 对 32 个线程执行组的称呼；AMD 称 wavefront，宽度依架构与产品而异。SIMT 不意味着每个线程在每个周期都独立发射不同指令。

线程语义与数据通路

SIMT 保留各线程的状态，共同指令仍可用类似 SIMD 的方式处理多份数据。成组执行不提供额外内存原子性，也不代替线程通信所需的同步。模型差异与写回问题见 附录 12。

03 · 底层逻辑与解决方式

对于相同操作、不同数据，成组发射可以分摊指令控制开销。当组内存在不同路径时，机器为各路径确定活跃线程集合，使不属于当前路径的线程不产生该路径指令的效果。在本例的简化模型中，A 与 B 分别执行，随后继续共同路径。

实验问题：半数分歧与交错分歧是否需要不同数量的执行路径？模式切换会更新路径数与 lane-slot 利用率。本例 A、B 各需一条等成本指令，忽略分支与汇合开销。

if (lane_condition) { A(); } else { B(); }

谓词化：给指令附加执行条件

编译器可能将短小的条件分支转换为带条件的指令。例如，if (x > 0) y = x + 1; 可用伪代码表示为 p = (x > 0); @p y = x + 1;。谓词 p 是每个线程各自的真假值：同一 Warp 发射加法时，p 为真的线程更新 y，p 为假的线程保持 y 不变。

条件跳转决定执行哪条路径；谓词化决定一条指令对哪些线程生效。它可能减少分支控制开销，但指令仍需调度，也不使未参与的线程同时改做其他操作。这是条件执行，不是分支预测。参考：CUDA 编程指南：分支谓词化。

lane-slot 利用率与执行时间

16 个线程各执行一次操作，有效工作量为 16。两条等长路径共提供 2 × 16 = 32 个 lane-slot，因此利用率 50%。真实路径长度可能不同，编译器可能采用上述谓词化，程序也可能受其他瓶颈限制。现代 NVIDIA 的独立线程调度改变控制和同步细节，但不会消除成组发射的效率约束；依赖隐式 warp 同步的程序可能不再满足正确性要求。

04 · 核心内容提炼

  • SIMT 提供标量线程的编程语义，并以线程组共享指令发射；线程与物理 lane 属于不同概念。
  • 组内路径不一致产生分歧；不同 warp 分别执行不同路径，不构成组内分歧。
  • Active mask 保持各线程的执行语义。分歧可能降低有效 lane 利用率，但对总耗时的影响取决于路径长度、编译结果及其他瓶颈。

1.6 执行机制对应的 GPU 硬件结构

SM（Streaming Multiprocessor）是 NVIDIA 的片上执行单元组织，包含线程状态、调度与执行等资源。AMD 的 CU 是相关硬件组织概念，内部结构并非一一对应。

01 · 问题

支持大量驻留线程、就绪组调度和成组执行，需要哪些硬件资源？Grid、Block、Warp 与 SM 分别处于什么层次？

02 · 背景

Kernel 是 GPU 上执行的核函数；一次启动（launch）安排一批线程执行它。Grid（线程块网格）是这次启动所包含的全部 Block 的集合，用于描述整批工作的规模与块编号；Block 则划分局部协作范围。

Grid：一次启动的全部线程块

例如 kernel<<<8, 128>>>(...) 表示一个包含 8 个 Block 的 Grid，每块有 128 个线程，共 1,024 个线程。块编号 blockIdx.x 为 0～7，块内线程编号 threadIdx.x 为 0～127；本例可用 i = blockIdx.x * 128 + threadIdx.x 确定各线程处理的数组元素。

Grid 是逻辑工作集合，不是一块物理硬件，也不要求所有 Block 同时执行。硬件将 Block 分配到可用 SM，资源不足时分批执行；因此 8 个 Block 不要求 8 个 SM。Grid 可按一维、二维或三维编号，这些维度便于对应数组、图像等数据，并不表示 SM 的物理排列。参考：CUDA：Thread Blocks 与 Grids。

在 NVIDIA GPU 中，Block 内的线程按 Warp 组织执行，SM 提供状态存储、调度与运算资源。Grid → Block → Thread 描述软件工作的组织；Warp 描述执行分组，SM 描述物理承载。这些概念不是逐层包含的同一种“核心”。AMD 的相关术语包括 work-group、wavefront 与 CU，具体组织依架构而异。

03 · 底层逻辑与解决方式

硬件资源与执行需求的对应关系

寄存器
保存 resident 线程状态；容量有限，所以不能无限驻留。
调度器
从 ready 组选择指令发射，覆盖其他组的等待。
运算通道（算术数据通路）
实际完成加法、乘法等运算的硬件电路，处理各活跃线程的操作数；选择与发射 Warp 指令则由调度和控制部分负责。
共享内存 / L1
提供片上数据存储。共享内存由程序显式管理，cache 通常由硬件管理，语义不同。
L2 / 显存
向执行单元供应数据。带宽影响总供给能力，延迟影响单次访问等待；增加线程数量无法突破带宽上限。

硬件将线程块分配到具有足够资源的执行单元。块中的线程被分为执行组，其状态占用片上资源；调度器选择就绪指令，运算通道处理活跃线程的数据，存储层次供应所需操作数。

图中的 8 个 SM/CU 与每格 12 个方块仅为示意，不代表真实数量、warp 宽度或块的固定分配。同一执行资源会随时间服务不同线程。Block 规定协作范围，warp 规定执行分组，SM 承载这些工作的硬件资源；这些概念分别属于软件组织、执行分组与硬件资源，不能统一等同于“核心”。

04 · 核心内容提炼

  • Grid 与 Block 组织软件任务，warp 组织线程执行，SM/CU 提供硬件资源；逻辑线程数量不等于物理运算通道数量。
  • 寄存器支持驻留状态，调度器选择就绪工作，算术通道完成操作，缓存与显存提供数据。各资源共同决定性能。
  • GPU 的吞吐优势要求可利用的独立工作和充分的数据供应；线程数量本身不是性能保证。

本章结论

CPU 通常侧重降低单线程执行延迟；GPU 通常通过调度其他驻留且就绪的线程束，覆盖部分线程的等待时间，提高执行资源利用率与整体吞吐量。
