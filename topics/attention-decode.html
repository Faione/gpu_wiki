01 · 矩阵乘法：输出轴与归约轴

若 A 为 M×K，B 为 K×N，则 C=AB 为 M×N。M、N 枚举输出位置，K 是为同一个输出累加的维度，称为归约轴（reduction axis）。

C[i,j] = Σₖ A[i,k] × B[k,j]，k = 0,…,K−1
(M×K) @ (K×N) → (M×N)

例如 3×4 乘 4×5 得到 3×5，每个输出累加 4 个乘积。元素乘法则是另一种运算：在 NumPy 中，A @ B 表示矩阵乘法，A * B 表示逐元素相乘（受广播规则约束）。

实验 1 · 选择一个输出，看它累加哪些元素

所有下标从 0 开始。深色为完整的输入行／列，橙色边框标出当前 k 对应的乘积。

A · 2×3
×
B · 3×2
=
C · 2×2

转置改变索引的解释

Bᵀ[j,k] = B[k,j]
S[i,j] = (QKᵀ)[i,j] = Σₖ Q[i,k]K[j,k]

最后一式比较的是 Q 的第 i 行与 K 的第 j 行。Kᵀ 将 key 的特征轴放到矩阵乘法的内侧。数学转置不要求先复制一份物理转置矩阵；是否需要搬运取决于布局与计算接口。

基础阅读：D2L §2.3：点积、矩阵向量乘法与矩阵乘法。硬件衔接：现有教材：矩阵乘法语义。

02 · 从点积到加权组合

点积同时受方向与长度影响

xᵀy = Σᵢ xᵢyᵢ = ‖x‖₂ ‖y‖₂ cos θ

例如，(1,2) 与 (2,−1) 的点积为 0，因此它们正交。两个非零向量点积为 0，夹角为 90°。一般情况下，x 放大 a 倍，点积也放大 a 倍。因此未归一化的点积不等于余弦相似度；Attention 的打分可以同时受方向与范数影响。

线性投影 xW 的每个输出也是点积。若 W 为 768×64，秩最多为 64，不可能对所有 768 维输入保持一一对应；但对受限的低维输入集合，仍可能保留所需信息。“投影”在神经网络中常泛指线性变换，不保证是几何上的正交投影。

非负、和为 1：结果落在凸包内

o = Σⱼ pⱼvⱼ，pⱼ ≥ 0，Σⱼpⱼ = 1

两个向量时，结果在线段上；三个不共线向量时，结果在三角形内部或边界上。这里把向量端点视为点。这个限制来自权重，与向量是否垂直无关。

实验 2 · 权重改变的是线段上的位置

坐标轴分别缩放以便阅读。线段表示可达到的端点集合；不表示时间或数据搬运。

Attention 的单头输出在所用 V 行向量的凸包内。随后拼接多头、乘 WO、加残差之后，不能再声称整个模块输出仍在这个原始凸包内。

03 · 手算一次 Attention

在常见实现中，输入隐藏状态 X 经学习到的权重产生 Q=XWQ、K=XWK、V=XWV。Q 用来发起匹配，K 用来打分，V 提供被混合的内容。它们不是三份手工指定的词义标签。

S = QKᵀ / √d + M
P = softmax(S)，每行沿 key 位置归一化
O = PV

M 为加性掩码：允许的位置加 0，禁止的位置在数学上加 −∞。常规缩放 √d 的动机是：若各分量独立、均值 0、方差 1，d 项点积的方差为 d；缩放后为 1。这是解释尺度的假设模型，不是每层数据必然满足的统计规律。

公式与缩放动机：Attention Is All You Need，§3.2。

稳定 softmax：统一减去最大值

m = maxⱼ sⱼ
pⱼ = exp(sⱼ−m) / Σₜ exp(sₜ−m)

分子分母共同乘 exp(−m)，比值不变；最大指数的输入变成 0，避免大正数指数溢出。有限精度下仍可能有小项下溢。若一整行都被 mask，−∞−(−∞) 无定义，必须按算子约定单独处理。

实验 3 · 一条 query，三个 key，两个输出分量

q = (a,0)
K = [(1,0), (0,1), (−1,0)]
V = [(1,0), (0,2), (2,2)]
d = 2；s = (a/√2, 0, −a/√2)

柱长表示归一化后的概率。a=0 且无掩码时，三个权重均为 1/3；屏蔽位置只改变参与归一化的集合。

默认 a=1 时，分数约为 (0.7071,0,−0.7071)，权重约为 (0.5760,0.2840,0.1400)，输出约为 (0.8560,0.8480)。第一项是 0.5760×1+0.2840×0+0.1400×2；第二项同样沿三个位置求和。

要记住两次归约：QKᵀ 沿特征 d 求和，PV 沿位置 L 求和。softmax 的 max 与 sum 也沿位置 L。

04 · Decode：只有一个新 query，仍要读取历史 KV

先考虑标准自回归模型、单请求、单层、单头，每轮处理一个新位置。将该位置的 k、v 写入缓存后，令 L 表示包含当前位置的可访问 KV 数量。历史 K、V 可复用；新 q 与所有可访问 key 重新计算分数。历史 query 通常不需要存入 KV cache。

阶段QK / V（取 dᵥ=d）逻辑分数形状
Prefill：一次处理 L 个提示 tokenL×dL×dL×L，带因果 mask
Decode：本轮一个新位置1×dL×d1×L

所以单步 decode 不需要计算完整 L×L 分数矩阵。融合实现还可以避免把完整的 1×L 分数写到全局内存。分块 prefill、推测解码和一次处理多个 query 不属于这里的单 token 简化模型。

加入 batch 与 GQA

逻辑形状可写为 Q：[B,Hq,1,d]，K：[B,Hkv,L,d]，V：[B,Hkv,L,dᵥ]。MHA 中 Hq=Hkv；GQA 让一组 query 头共享一个 KV 头；MQA 的 Hkv=1。这是逻辑形状，实际缓存可以采用不同布局或分页。

KV 头共享：GQA 原论文。

先算数据量，再提出性能假设

每层 KV cache 字节数 = B × L × Hkv × (d+dᵥ) × b
QKᵀ 与 PV 的运算量 ≈ 2 × B × Hq × L × (d+dᵥ) FLOP

b 是每个缓存元素的字节数，乘和加各记一次 FLOP。缓存容量公式不含分页空洞、量化尺度及额外元数据；多层时再乘层数。运算量不含 softmax、位置变换和线性投影。

实验 4 · KV 容量不等于实际总线流量

固定 B=1、Hq=32、d=dᵥ=128、缓存元素 2 字节。假设每个 KV 元素本轮只从外部存储读一次、忽略其他流量，计算理想化比值。

小 batch 的长上下文 decode 常需要优先检查 KV 读取与可并行工作是否充足。GQA 提供共享 KV 的机会，但若多个 query 头分别重读缓存，真实流量会增加。缓存命中也可能减少外部读取；不能直接用缓存容量替代 profiler 的带宽数据。

Decode 的工作划分背景：Flash-Decoding 作者介绍。本文的容量与 FLOP 示例由上述形状直接推导，不是设备跑分。

05 · 分块后如何保持结果正确

Q(KᵀV) 与 (QKᵀ)V 在精确算术下相等，但 Attention 中间有 softmax，不能直接移走它。减少中间存储需要保留归一化所需的统计量。

每块保存三个量

将 key 位置划为不重叠的块 A、B。以下 s 已完成缩放和掩码。对于至少有一个有效位置的块：

mA = maxⱼ∈A sⱼ
ℓA = Σⱼ∈A exp(sⱼ−mA)
uA = Σⱼ∈A exp(sⱼ−mA) vⱼ

m、ℓ 为标量，u 为 dᵥ 维向量。u 是未归一化的加权和，局部输出为 u/ℓ。两个块的指数使用不同基准，合并前要重新缩放。

m = max(mA,mB)
α = exp(mA−m)，β = exp(mB−m)
ℓ = αℓA + βℓB
u = αuA + βuB
o = u / ℓ

推导只需观察 exp(s−m)=exp(s−mA)exp(mA−m)。这同时支持按顺序读块的 online softmax，以及不同工作单元计算各块后再合并。精确数学下结果一致；浮点归约顺序改变时不保证逐位相同。

为什么不能直接平均局部输出？

A 只有一个 score=0，B 只有一个 score=ln 3。各块内部概率都是 1，但全局概率为 1/4 和 3/4；简单平均会得到错误的 1/2 和 1/2。

空块怎么处理？

空块或全 mask 块的有效质量为 0，应跳过合并或显式设为零贡献，避免计算 −∞−(−∞)。最终 ℓ=0 的整行要遵循接口语义。

FlashAttention 利用分块和在线归一化降低中间结果的 IO。Decode 的 query 很少时，还可以沿 KV 长度拆分任务以增加并行度，然后付出统计量合并的代价。块越多并不必然越快：小块会增加调度、重复读 q 与合并开销。

算法依据：FlashAttention，§3 与 Algorithm 1；沿 KV 切分的背景见 Flash-Decoding。

06 · 连接 Ascend C：从公式到数据与依赖

昇腾是 NPU 平台，Ascend C 是算子开发体系。可以迁移现有 GPU 教材中“工作划分、数据复用、流水依赖”的分析方法；不能将 Warp、SM 或 shared memory 与昇腾对象直接一一对应。

数学工作实现时先回答需要学习的概念
q 与 K 的点积谁负责哪些 key？q 是否重复搬入？核间切分、块大小、实际布局与步长
max、exp、sum、重缩放哪些临时数据可留在片上？Vector 运算、UB 空间、归约及精度
概率乘 V 并累加输出分量怎样分配？部分和在哪里？乘加、累加类型、Vector / Cube 路径选择
读取下一块、处理当前块缓冲区何时可读、何时可复用？搬运、队列、事件依赖与双缓冲
跨块合并谁读取统计量并完成最终归一化？工作区、阶段边界与最终归约

先区分几类存储

GM 保存全局数据；UB 支持 Vector 侧数据与临时结果；Cube 路径涉及 L1、L0A/L0B 输入缓冲和 L0C 累加结果。容量、数据路径与支持的布局随产品而变。这里不把 UB 画成 Cube 必经的一级缓存，也不假定所有算子都必须用 Cube。

架构参考：CANN 8.0：Storage Units。这里只引用存储职责；实际开发应切换到目标产品与已安装 CANN 版本。

第一条设备学习路线

  1. Add：建立 Host 到 Device 的完整流程，识别 GM 与 LocalTensor。
  2. ReduceSum / ReduceMax：练习归约、尾块与有效元素范围。
  3. 稳定 softmax：组合 max、减法、exp、sum、除法，核对与 NumPy 的误差。
  4. 单 query Attention：先完成正确的 QKᵀ → softmax → PV，再加入分块状态。
  5. 优化：用实际 shape 比较块大小、缓存复用及 KV 切分；测量以后再决定融合与流水策略。

在 TPipe/TQue 编程方式中，先掌握缓冲分配、入队、出队及释放的生命周期。Host 侧 tiling 决定切分参数，Device 按这些参数处理数据。双缓冲只有在依赖正确且存在可交叠工作时才可能获益。

开发入口：CANN 9.0：基于 TPipe 和 TQue 编程；CANN 8.0：Host / Kernel 与 Tiling 入门。文档版本用于定位来源，实际使用时需匹配开发环境版本。

实现 Ascend C Kernel 前，需要明确设备型号、CANN 版本、B/Hq/Hkv/L/d、缓存布局与 dtype，据此确定分块和缓冲配置。

07 · NumPy 实验与学习顺序

先比较完整计算和分块计算，再换实现语言。下面的参考程序只处理单 query、二维连续 K/V、无 mask；使用 float64 检验数学关系，不代表设备端精度配置。

import numpy as np


def attention_full(q, K, V):
    s = (K @ q) / np.sqrt(q.size)
    p = np.exp(s - s.max())
    p /= p.sum()
    return p @ V


def attention_blocked(q, K, V, block_size):
    if block_size <= 0 or len(K) == 0:
        raise ValueError("Need positive block size and nonempty KV")
    m, total = -np.inf, 0.0
    acc = np.zeros(V.shape[1], dtype=np.float64)
    for start in range(0, len(K), block_size):
        kb = K[start:start + block_size]
        vb = V[start:start + block_size]
        s = (kb @ q) / np.sqrt(q.size)
        next_m = max(m, s.max())
        scale = np.exp(m - next_m)
        weights = np.exp(s - next_m)
        acc = scale * acc + weights @ vb
        total = scale * total + weights.sum()
        m = next_m
    return acc / total


if __name__ == "__main__":
    rng = np.random.default_rng(7)
    q = rng.normal(size=8)
    K = rng.normal(size=(37, 8))  # 37 checks a partial final block
    V = rng.normal(size=(37, 6))  # d_v need not equal d
    reference = attention_full(q, K, V)
    for block in [1, 7, 16, 37, 64]:
        result = attention_blocked(q, K, V, block)
        np.testing.assert_allclose(result, reference, rtol=1e-12,
                                   atol=1e-12)
        print(block, np.max(np.abs(result - reference)))

08 · 记忆卡与自测

① (M×K) @ (K×N) → (M×N)
② C[i,j] = Σₖ A[i,k]B[k,j]
③ sⱼ = Σₖ qₖK[j,k] / √d
④ pⱼ = exp(sⱼ−m) / Σₜ exp(sₜ−m)
⑤ oᵣ = Σⱼ pⱼV[j,r]
⑥ 分块合并：先统一指数基准，再合并分母与加权和

先口述答案，再展开核对。能答对新例子，才算掌握，而不只是认得公式。

1. A 为 2×3，B 为 3×4，C[1,2] 是什么？

C 为 2×4。C[1,2]=A[1,0]B[0,2]+A[1,1]B[1,2]+A[1,2]B[2,2]。输出下标固定，归约下标遍历。

2. 一个 query，100 个 key，每个 64 维，分数和输出是什么形状？

分数为 1×100；若 V 为 100×64，输出为 1×64。前者沿 64 维求和，后者沿 100 个位置求和。

3. 给所有分数加 1000，数学上的 Attention 输出会变化吗？

不会。softmax 对共同平移不变；但直接计算 exp(s+1000) 可能溢出，应先减最大值。

4. 为什么不能把每个 KV 块的局部 Attention 输出直接相加或平均？

各块有自己的归一化分母。要按各块在全局分母中的质量重新加权；m、ℓ、u 或等价的 log-sum-exp 信息用于恢复这一关系。

5. GQA 的 KV 头从 32 减到 8，缓存容量与计算量都变为 1/4 吗？

固定其他量时，KV 容量为原来的 1/4。若 query 头数仍为 32，QKᵀ 与 PV 的主要 FLOP 不因 KV 共享而降到 1/4。真实流量收益还依赖复用方式。

6. 数学结果相同、FLOP 更少，就一定更快吗？

不一定。搬运、可并行任务数量、填充浪费、临时空间、启动和同步都影响耗时；浮点归约顺序也会影响误差。
